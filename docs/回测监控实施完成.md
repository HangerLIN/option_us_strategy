## 📈 可用的PromQL查询

### 基础查询

```promql
# 回测API是否在线
up{job="backtest_api"}

# 回测API请求速率 (QPS)
rate(backtest_api_requests_total[5m])

# 回测API P95延迟
histogram_quantile(0.95, 
  rate(backtest_api_latency_seconds_bucket[5m])
)

# 回测API错误率
(
  sum(rate(backtest_api_requests_total{status_code=~"5.."}[5m]))
  /
  sum(rate(backtest_api_requests_total[5m]))
) * 100
```

### 业务查询

```promql
# 回测查询速率
rate(backtest_runs_queried_total[5m])

# 回测指标查询成功率
(
  rate(backtest_metrics_queried_total{found="true"}[5m])
  /
  rate(backtest_metrics_queried_total[5m])
) * 100

# 数据库查询P95延迟
histogram_quantile(0.95,
  rate(backtest_db_query_seconds_bucket{operation="list_runs"}[5m])
)

# 当前回测总数
backtest_total_runs
```

## 📝 注意事项

### API端点冲突解决

⚠️ **重要**: 原来的 `/metrics/{run_id}` 端点已改为 `/backtest-metrics/{run_id}`

**原因**: Prometheus的metrics端点固定为 `/metrics`，与原回测指标查询端点冲突。

**影响**: 如果有外部系统调用回测指标查询API，需要更新调用路径：
- ❌ 旧: `GET /metrics/123`
- ✅ 新: `GET /backtest-metrics/123`

### 端口配置

默认配置假设回测API运行在 **8006** 端口。

如果实际端口不同，需要修改：
```yaml
# infra/prometheus/prometheus.yml
- job_name: 'backtest_api'
  static_configs:
    - targets: ['host.docker.internal:YOUR_ACTUAL_PORT']
```

### 采集频率

回测API的采集间隔设为30s（低于实盘服务的10-15s），因为：
- 回测API不是实时关键路径
- 降低Prometheus负载
- 回测查询频率较低

如需调整，修改 `scrape_interval` 配置。
