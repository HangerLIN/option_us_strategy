# 回测参数配置指南

本文档详细说明回测系统中所有可配置的参数，包括命令行参数、环境变量配置和策略参数。

---

## 一、命令行参数（CLI Arguments）

通过 `python -m apps.backtest.main` 运行回测时可配置的参数：

### 1.1 必需参数

| 参数 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `--start` | datetime (ISO-8601) | 回测开始时间（包含），必须带时区 | `2025-09-02T09:30:00-04:00` |
| `--end` | datetime (ISO-8601) | 回测结束时间（不包含），必须带时区 | `2025-09-15T16:00:00-04:00` |

### 1.2 可选参数

| 参数 | 类型 | 默认值 | 可选值 | 说明 |
|------|------|--------|--------|------|
| `--universe` | string | `ref_market_cap:GLOBAL` | 任意universe标识 | 股票池规格，默认使用市值快照 |
| `--symbols` | list[string] | `None` | 如 `NVDA AAPL MSFT` | 调试用：限定回测的股票列表，覆盖universe |
| `--batch-id` | string | 自动生成 | 任意字符串 | 批次标识符，用于区分不同回测任务 |
| `--mode` | string | `logic` | 保留字段 | 预留给未来策略变体使用 |
| `--signal-mode` | string | `recompute` | `recompute`, `db` | 信号源模式：<br>• `recompute`: 重新计算信号<br>• `db`: 从数据库读取已有信号 |
| `--track` | string | `option` | `option`, `equity` | 执行轨道：<br>• `option`: 期权交易（默认）<br>• `equity`: 纯股票交易（Track A） |
| `--metrics-mode` | string | `tfe` | `fixed`, `tfe`, `both` | 股票指标聚合模式（已废弃，仅支持tfe） |
| `--risk-mode` | string | `inproc` | `inproc`, `http` | 风险预检后端：<br>• `inproc`: 进程内风控<br>• `http`: HTTP调用风控服务 |
| `--paper` | int | `1` | `0`, `1` | 预留标志位，用于区分模拟/实盘模式 |

### 1.3 命令行示例

```bash
# 基础回测
python -m apps.backtest.main \
  --start "2025-09-02T09:30:00-04:00" \
  --end "2025-09-15T16:00:00-04:00"

# 指定股票、信号模式和风控模式
python -m apps.backtest.main \
  --start "2025-09-02T09:30:00-04:00" \
  --end "2025-09-15T16:00:00-04:00" \
  --symbols NVDA AAPL MSFT \
  --signal-mode recompute \
  --risk-mode inproc \
  --track option

# 股票轨道回测
python -m apps.backtest.main \
  --start "2025-09-02T09:30:00-04:00" \
  --end "2025-09-15T16:00:00-04:00" \
  --symbols AMD \
  --track equity
```

## 七、调优建议

### 7.1 性能优化

1. **信号模式选择**：
   - 初次测试用 `--signal-mode recompute`
   - 重复回测用 `--signal-mode db`（需先运行一次recompute）

2. **风控模式选择**：
   - 单机回测用 `--risk-mode inproc`（性能更好）
   - 分布式回测用 `--risk-mode http`（可共享风控状态）

3. **股票池限制**：
   - 使用 `--symbols` 限定少量股票进行快速验证
   - 完整回测使用完整 universe

### 7.2 参数调整场景

| 场景 | 调整参数 | 建议值 |
|------|----------|--------|
| 高波动市场 | `VIX_GATE` | 提高到 `25-30` |
| 低波动市场 | `VIX_GATE` | 降低到 `15-18` |
| 增加持仓容量 | `MAX_CONCURRENT_TOP` | 增加到 `5-10` |
| 严格风控 | `DAILY_LOSS_R` | 降低到 `2-2.5` |
| 延长信号TTL | `TTL_BUY` | 增加到 `300-600` |
| 缩短冷却期 | `COOLDOWN_BUY` | 降低到 `300-480` |

2. **环境变量**（`.env` 或系统环境）

## 十一、回测完整链路：如何复用实盘信号，确保“同一套信号”

### 11.1 一致性目标

- 使用与实盘完全一致的信号规则和参数；
- 两种方式均可保障一致性：
  - recompute 模式：在回测中直接调用与实盘相同的 `SignalEngine` 逻辑重新计算；
  - db 模式：直接重放实盘期间已持久化的“被接收”的信号。

### 11.3 两条复现路径

- 模式A（推荐，重算一致性最高）：
  1) 通过 `apps/backtest/main.py` 先生成回测用 Top5 快照；
  2) 使用 `--signal-mode recompute`，由引擎重算信号；
  3) 执行与风控在回测侧按相同规则进行预检和落单。

- 模式B（重放实盘已采纳信号，和实盘完全一致）：
  1) 确认实盘服务已将信号写入 `bt_signals`（默认已开启，见上文持久化代码）；
  2) 回测时使用 `--signal-mode db`，并设置相同时间窗口与 `--symbols`；
  3) 回测侧仅重放 accepted=true 的信号，不再做信号筛选差异。

示例（重放实盘信号）：

```bash
python -m apps.backtest.main \
  --start "2025-09-10T09:30:00-04:00" \
  --end   "2025-09-10T16:00:00-04:00" \
  --symbols NVDA AAPL MSFT \
  --signal-mode db \
  --risk-mode inproc \
  --track option
```

### 11.4 一致性注意事项

- 交易日股票池：重算模式依赖回测批次的 Top5 快照；若要对齐实盘，当天的 Top5 生成规则和参数需要一致。
- 限额与风控：实盘的风险限额来自 `apps/risk_svc` 的限额快照；回测重算时使用当前快照，若与实盘日不同会有微小差异。严格对齐需冻结同日限额配置。
- 指标与行情：确保 `bars1m_equity` 与 `indicators_eq_1m` 的数据完整且与实盘一致（时区按UTC存储，代码中已统一处理）。
- 时间窗口：`--start/--end` 要覆盖实盘产生信号的分钟；db 模式只会重放窗口内的 accepted 信号。
