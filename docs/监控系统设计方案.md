# 监控系统设计方案（Paper/Live 交易）

> 适用范围：除回测外的所有在线服务（md_gw / rt_engine / signal_svc / risk_svc / exec_svc / pnl_svc）。
> 技术栈：Prometheus + Alertmanager + Grafana；FastAPI `/metrics` 暴露；结构化日志。

> 前提与取舍：当前系统仅使用分钟级（1m）K线与指标，未接入 Level2。以下方案为“核心精简版”，去除了对 L2、期权链细节和高频执行依赖的指标，仅保留分钟级必需项。

---

## 1. 目标与边界

- 覆盖 Paper/Live 全链路：行情接入 → 分钟聚合与指标 → 信号生成 → 风险控制 → 执行 → 持仓与盈亏。
- 监控四层面：可用性（Health/就绪）、性能（延迟/速率）、正确性（数据新鲜度/约束）、业务健康（PnL/风险/成交）。
- 输出三类资产：
  - SLI/SLO 清单与告警规则（PrometheusRule）。
  - 仪表盘布局（Grafana 面板分组）。
  - 值班手册（Runbook：定位 → 缓解 → 验证）。

---

## 2. 总体架构

- 每个服务（FastAPI）暴露：`/healthz`（liveness）与 `/metrics`（Prometheus）。
- Prometheus 以 job 维度抓取：`signal_svc:8000`、`exec_svc:8001`、`risk_svc:8002`、`pnl_svc:8003`、`rt_api:8007`、`md_gw:8005`（见 `infra/prometheus/*.yml`）。
- Alertmanager 统一路由：Critical → 电话/IM；High → IM；Low → 邮件/IM；消息体包含 runbook 链接与最近面板快照。
- Grafana 仪表盘：按服务与场景组织（总览 / 服务深度 / 交易链路 / 风险与PnL / 订单与成交 / 数据与时延）。

## 3. 监控对象与关键指标

### 3.1 md_gw（行情网关）
- 可用性：
  - `rt_ibkr_connection_status`（1/0）—— IBKR 连接状态。
  - `rt_ibkr_reconnections_total` —— 重连计数/速率。
- 性能与数据：
  - `rt_ticks_received_total`、`rt_subscribed_symbols_count` —— 订阅规模与吞吐。
  - `bars_latency_seconds` —— 分钟闭合→处理延迟（P95 ≤ 1.5s）。
  - `rt_cached_bars_count` —— 聚合缓存深度。
  - Top5：`rt_top5_candidates_count`、`rt_top5_calculation_seconds`、`rt_top5_selection_total`。

### 3.2 rt_engine（分钟聚合与指标/Top5）
- 性能：
  - `bars_latency_seconds` —— 分钟闭合端到端时延（P95/SLO）。
  - `rt_indicator_calculation_seconds`、`rt_indicator_failures_total` —— 指标计算延迟与失败率。
- 数据新鲜度：
  - `last_bar_ts_diff_seconds`（派生）—— 当前时间与最近入库分钟差；阈：≤ 90s。

### 3.3 signal_svc（信号生成）
- 产出与质量：
  - `signals_emitted_total{signal_code}` —— 分信号数量（含 AM 系列）。
  - `signals_filtered_total{reason}` —— 过滤原因统计（VIX Gate/时间窗/流动性等）。
  - `signal_generation_latency_seconds` —— 每分钟计算时延（P95）。
  - 说明：聚焦分钟级触发的产量与时延，去除 WS 推送与高频速率指标。

#### 交易信号类型覆盖（买/卖）

- 覆盖范围：所有“买入/卖出/退出/时间清仓”类信号均以 `signal_code` 标签统计；若启用 `record_signal_by_type`，则额外以 `side ∈ {buy,sell,exit}` 标签聚合。
- 买入（示例）：`SIG_OPEN_CHASE_BUY`、`SIG_REBOUND_BUY`、`SIG_PM_BOTTOM_A2|A3|A4`、`SIG_AM_BOTTOM_A1`、`SIG_AM_CONFLUENCE_BUY_A2`。
- 卖出/退出（示例）：`SIG_AM_SELL_C1`、`SIG_AM_CONFLUENCE_SELL_S2`、`SIG_EXIT_UPPER_TAP_X2`、`SIG_EXIT_BOX2MID`、`SIG_TIME_CLEAR_12_14`、风控强平（见 `risk_force_close_total`）。
- PromQL 示例：
  - 按信号代码：
    - `sum by (signal_code) (increase(signals_emitted_total[5m]))`
  - 按买/卖侧（若启用 `signal_by_type_total`）：
    - `sum by (side) (increase(signal_by_type_total[5m]))`
  - 新增 AM 系列概览：
    - `sum by (signal_code) (increase(signals_emitted_total{signal_code=~"SIG_AM_.*"}[15m]))`

### 3.4 risk_svc（风控）
- 风控态势：
  - `risk_kill_switch_state`、`risk_vix_last`、`risk_used_r`、`risk_drawdown_r`。
  - `position_count`、`total_exposure_usd`、`capital_utilization_pct`。
  - `limit_usage_pct{name}`、`limit_approaching_total{name}`。
- 事件：
  - `risk_block_events_total{reason_code}` —— 被拒单原因分布。
  - `risk_force_close_total{reason_code}` —— 强平触发。

### 3.5 exec_svc（执行）
- 订单生命周期：
  - `orders_submitted_total{mode}`、`orders_accepted_total{mode}`、`orders_blocked_total{stage,reason}`、`orders_conversion_rate`。
  - `order_execution_latency_seconds`、`order_timeout_total`。
  - 说明：不监控滑点/Δ偏离/链抓取等 L2 相关细节。

### 3.6 pnl_svc（持仓与盈亏）
- 盈亏与效率：
  - `pnl_realized_today_usd`、`pnl_unrealized_today_usd`、`pnl_cumulative_usd`。
  - `pnl_trades_count_today`、`pnl_win_rate_pct`。
  - 说明：去除分布型与持仓结构细粒度指标，保留最小业绩看板。

## 4. 端到端 SLI/SLO（核心最小集）

- 数据：`bars_latency_seconds{quantile="0.95"} ≤ 1.5s`；`last_bar_ts_diff_seconds ≤ 90s`。
- 信号：`signal_generation_seconds` P95 ≤ 0.5s。
- 执行：`orders_conversion_rate ≥ 0.8 (Paper) / 0.6 (Live)`；`order_execution_latency_seconds` P95 ≤ 3s。
- 风控：`risk_kill_switch_state==1` 连续 >10m 告警；`risk_drawdown_r > 3` Critical。
- （可选）PnL：`pnl_win_rate_pct` 3日均值 < 30% 触发 Low。

注：本节为监控阈值，用于告警与达标评估。

---

## 5. 告警规则（核心版）

- Critical：
  - md_gw 离线：`ibkr_connection_status == 0 for 60s`。
  - 数据卡死：`bars_latency_seconds{quantile="0.95"} > 5 for 5m`。
  - 交易熔断：`risk_drawdown_r > 3 or kill_switch_state==1 for 1m`。
  - 执行阻断：`orders_conversion_rate < 0.2 for 2m`（Live）。
 - High：
  - 指标超时：`histogram_quantile(0.95, sum(rate(indicator_calculation_seconds_bucket[5m])) by (le)) > 1`。
  - 强平激增：`increase(risk_force_close_total[15m]) > 3`。
  - 低转化率：`orders_conversion_rate < 0.4 for 5m`（Live）。
 - Low：
  - 胜率走弱：`avg_over_time(pnl_win_rate_pct[3d]) < 0.3`。

注：Paper 与 Live 的阈值应分环境标签区分（`env="paper|live"`）。

## 6. 仪表盘设计（Grafana，核心版）

- 总览（Overview）：环境切换、服务存活、端到端时延、近 1h 告警摘要。
- 数据与聚合：bar 延迟、数据新鲜度、指标计算时延。
- 信号：分信号数量（含 AM 系列）、过滤原因、生成时延。
- 风控：VIX、Kill Switch、Used R/Drawdown、风控拒单/强平事件。
- 执行：订单漏斗（提交→接受→成交）、成交延迟直方图、超时计数。
- PnL：日内/累计 PnL、当日笔数、胜率。

## 7. 健康与就绪

- Liveness：`/healthz` 返回 `status=ok` 即存活；
- Readiness：建议增加 `/readyz`（检测 DB/Redis/IBKR 就绪），作为 Kubernetes/进程管理的 readiness 探针；
- Metrics：所有服务暴露 `/metrics`；Prometheus 每 5s-15s 抓取。

## 8. 数据新鲜度与链路验证

- 数据新鲜度：
  - 计算 `now() - max(ts_end)` 的秒数，落 `last_bar_ts_diff_seconds`（可在 rt_engine 周期写 Gauge）。
- 链路验证（合成探针）：
  - 每日 RTH 开盘后由 `signal_svc` 发一条“合成心跳信号”（不进入执行），监控 `signals_emitted_total → risk_block_events_total` 的传递时间（< 1s）。

## 12. 纸交/实盘差异化监控

- 统一指标体系，使用 `env=paper|live`、`mode=paper|live` 区分；
- Paper：强调端到端延迟、规则正确性与风控闭环（不关注成交与滑点）；
- Live：强调订单漏斗、成交延迟、滑点、链抓取失败、VIX Gate、强平与熔断。

## 13. 指标计算方案（按服务）

说明：统一使用 Prometheus Counter/Gauge/Histogram。分布指标统一使用 Histogram 并明确桶，Grafana 侧用 `histogram_quantile` + `rate` 计算 P95/P99。

 - md_gw：
  - `rt_ibkr_connection_status`（Gauge）：连接建立=1，断开=0；在连接事件回调与心跳定时任务中刷新。
  - `rt_ibkr_reconnections_total`（Counter）：每次重连成功自增 1。
  - `rt_ticks_received_total`（Counter）：每收到一笔 tick 自增（当前实现带 `symbol` 标签）。
  - `rt_subscribed_symbols_count`（Gauge）：订阅变更时设置当前订阅数。
  - `bars_latency_seconds`（Histogram）：在 1m K 线闭合落库后，记录“闭合时间→完成处理”的耗时；建议桶 `(0.05, 0.1, 0.25, 0.5, 1, 2.5, 5, 10, 20)`。
  - `rt_cached_bars_count`（Gauge）：聚合缓存/待处理队列长度，按周期（例如每 5 秒）刷新（实现需 `symbol,timeframe` 标签）。
  - `rt_top5_candidates_count`（Gauge）：Top5 生成后设置候选数量。
  - `rt_top5_calculation_seconds`（Histogram）：Top5 计算耗时，桶 `(0.1, 0.5, 1.0, 2.0, 5.0, 10.0)`。
  - `rt_top5_selection_total`（Counter）：每次成功产出 Top5 自增。

 - rt_engine：
  - `bars_latency_seconds`：与 md_gw 对齐，可在完成指标计算后再观测一次，作为链路端到端时延基准。
  - `rt_indicator_calculation_seconds`（Histogram）：单分钟指标计算耗时（BOLL/RSI/ATR/MACD/StochRSI/OBV 等），桶 `(0.001, 0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1.0)`；带 `indicator` 标签。
  - `rt_indicator_failures_total`（Counter）：异常捕获后按 `indicator,reason` 标签自增。
  - `last_bar_ts_diff_seconds`（Gauge）：`now() - max(ts_end)`，由定时任务每 15 秒计算并写入。

 - signal_svc：
  - `signals_emitted_total{signal_code}`（Counter）：每次产出信号按代码自增（含 AM/E/S 系列）。
  - `signals_filtered_total{reason}`（Counter）：被过滤原因（`VIX_GATE/TIME_WINDOW/LIQ/COOLDOWN/CONFLICT/...`）。
  - `signal_generation_latency_seconds`（Histogram）：每分钟信号扫描/生成耗时，桶 `(0.01, 0.05, 0.1, 0.25, 0.5, 1.0, 2.0)`。

- risk_svc：
  - `risk_kill_switch_state`（Gauge）：1=只出不入；0=开放。
  - `risk_vix_last`（Gauge）：VIX 最新值（分钟采样）。
  - `risk_used_r`、`risk_drawdown_r`（Gauge）：分钟维度刷新组合使用的 R 与回撤。
  - `position_count`、`total_exposure_usd`、`capital_utilization_pct`（Gauge）：组合维度持仓数、名义敞口、资金使用率。
  - `limit_usage_pct{name}`（Gauge）：各类限额使用率（并发、单标的敞口等）。
  - `limit_approaching_total{name}`（Counter）：接近阈值时记录一次事件。
  - `risk_block_events_total{reason_code}`（Counter）：拒单事件（`VIX_GATE/NOON_WINDOW/LIQ/WIDE_SPREAD/CONCURRENCY/...`）。
  - `risk_force_close_total{reason_code}`（Counter）：强平事件（`STOP_LOSS/CUTOFF/IV_CAP/...`）。

 - exec_svc：
  - `orders_submitted_total{mode}`、`orders_accepted_total{mode}`、`orders_blocked_total{stage,reason}`（Counter）：订单漏斗各阶段计数。
  - `orders_conversion_rate`（Gauge）：`accepted/submitted`；在提交/接受/阻断任一事件发生时重算并写入。
  - `order_execution_latency_seconds{stage}`（Histogram）：从下单到成交的延迟，桶 `(0.1, 0.5, 1.0, 2.0, 5.0, 10.0, 30.0, 60.0)`。
  - `orders_timeout_total{timeout_type}`（Counter）：TTL 超时撤单事件。

- pnl_svc：
  - `pnl_realized_today_usd`、`pnl_unrealized_today_usd`、`pnl_cumulative_usd`（Gauge）：成交或行情刷新时更新。
  - `pnl_trades_count_today`（Gauge）：当日成交笔数。
  - `pnl_win_rate_pct`（Gauge）：滚动统计胜率（例如最近 N 笔/当日）。

## 14. 埋点设计（按服务与代码位置）

统一约束：
- 标签基数控制：`signal_code`、`reason_code`、`side/mode/stage` 使用有限枚举；避免在高频指标上使用 `symbol` 标签。
- 采样与频率：Histogram 仅在关键路径观测一次；Gauge 在状态变更时设置，或定时刷新；Counter 在离散事件发生时自增。
- 统一库：使用 `libs/infra/metrics.py` 导出的公共函数，避免重复定义。

- md_gw（`apps/md_gw/main.py`）：连接/重连回调、tick 回调、订阅管理、聚合完成、Top5 任务处进行埋点（参照上节指标对应 API）。
- rt_engine（`apps/rt_engine/aggregator.py`）：指标计算包裹耗时与异常捕获；数据新鲜度定时任务写 Gauge。
- signal_svc（`apps/signal_svc/engine.py`）：信号产出/过滤点位；生成主循环包裹耗时。
- risk_svc（`apps/risk_svc/main.py`/`service.py`）：状态/组合/限额 Setter；拒单与强平事件埋点。
- exec_svc（`apps/exec_svc/main.py`）：提交/接受/阻断三处分别调用订单计数与转换率更新；成交耗时与超时事件。
- pnl_svc（`apps/pnl_svc/consumer.py`）：成交流与行情刷新时同步写入 PnL 与胜率。

## 15. Grafana 页面设计（详案）

变量：`env`（paper|live），`service`（signal_svc/exec_svc/...），`instance`（主机:端口）。

页面一：Trading Overview（总览）
- 面板：
  - Bar 延迟 P95（秒）：
    ```
    histogram_quantile(0.95, sum(rate(bars_latency_seconds_bucket{instance=~"$instance"}[$__interval])) by (le))
    ```
  - 数据新鲜度（秒）：
    ```
    last_bar_ts_diff_seconds{instance=~"$instance"}
    ```
  - 信号产量（15 分钟）：
    ```
    sum by (signal_code) (increase(signals_emitted_total{instance=~"$instance"}[15m]))
    ```
  - 订单转化率：
    ```
    orders_conversion_rate{instance=~"$instance"}
    ```
  - Kill Switch：
    ```
    risk_kill_switch_state{instance=~"$instance"}
    ```

页面二：Data & Aggregation（数据与聚合）
- 面板：
  - 指标计算 P95：
    ```
    histogram_quantile(0.95, sum(rate(indicator_calculation_seconds_bucket[$__interval])) by (le))
    ```
  - 订阅规模：`subscribed_symbols_count`
  - 缓存深度：`cached_bars_count`
  - Top5 候选与耗时：`top5_candidates_count`；
    ```
    histogram_quantile(0.95, sum(rate(top5_calculation_seconds_bucket[$__interval])) by (le))
    ```

页面三：Signals（信号）
- 面板：
  - 分代码产量（15 分钟）：
    ```
    increase(signals_emitted_total[15m]) by (signal_code)
    ```
  - 过滤原因（15 分钟）：
    ```
    increase(signal_filtered_total[15m]) by (reason)
    ```
  - 生成时延 P95：
    ```
    histogram_quantile(0.95, sum(rate(signal_generation_seconds_bucket[$__interval])) by (le))
    ```

页面四：Risk（风控）
- 面板：
  - VIX：`risk_vix_last`
  - Used R / Drawdown：`risk_used_r`、`risk_drawdown_r`
  - 拒单与强平（15 分钟累计）：
    ```
    increase(risk_block_events_total[15m]) by (reason_code)
    ```
    ```
    increase(risk_force_close_total[15m]) by (reason_code)
    ```
  - 限额使用率：`limit_usage_pct`（表格/单值）

页面五：Execution（执行）
- 面板：
  - 订单漏斗（当日累计）：提交/通过/阻断（单值）
  - 转化率：`orders_conversion_rate`
  - 成交延迟 P95：
    ```
    histogram_quantile(0.95, sum(rate(order_execution_latency_seconds_bucket[$__interval])) by (le))
    ```
  - 超时次数（近 1h）：
    ```
    increase(order_timeout_total[1h])
    ```

页面六：PnL（盈亏）
- 面板：
  - 当日/累计 PnL：`pnl_realized_today_usd`、`pnl_unrealized_today_usd`、`pnl_cumulative_usd`
  - 当日笔数与胜率：`pnl_trades_count_today`、`pnl_win_rate_pct`
