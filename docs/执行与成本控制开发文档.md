# 执行与成本控制开发文档

## 1) 目标与边界

- **目标**：把上游 `signals` 转换为**合规/可控成本**的订单流；价差宽时压滑点，卖点/清仓场景快速成交。
- **边界**：仅覆盖**委托生成、价格与时效策略、撤补与重试、成本度量与监控**。
   风控（时间窗/熔断/封禁/IV/VIX）由 `risk-service` 判定；成交后 **持仓/PnL** 由 `pnl-service` 维护。

- **连接**：与 IB Gateway（`md-gw`）同 VPC；TCP 低延迟；断线自动重连；**幂等**：`clientOrderId = trace_id`。
- **路由**：`SMART`；`outsideRth=false`；`tif=DAY`；仅 RTH 交易。
- **价格对齐**：按合约 **minTick** 四舍五入；不合法直接拒单并告警。
- **去重**：同一 `dedupe_key = symbol+signal_code+window` 只允许一张活动单。

## 3) 前置约束与风控联动（这一步最关键）

执行前必须做**统一 Pre-check**（本地兜底 + `risk-service` 二次确认）：

### 3.1 本地兜底（不依赖风控）

- **期权可交易性**：`OI≥500 && Volume≥100 && spread ≤ max($0.10, 0.05*mid)`，否则不下单。
- **DTE/档位**：仅 `DTE 2–7，OTM +2~+5`（可选：`Δ≈0.35–0.45`），否则不下单。
- **A1 Gate（午后抄底前置）**：若 `signal.payload.a1_gate=false`（如 `close ≥ open_today` / 近 0–5 日未进 Top5 / 当日高开且期权价 > 当日开盘价），**不下单**（卖点不受此限）。
- **卖点优先**：同分钟如有 `SIG_EXIT_*`，先处理卖出/清仓，再评估买入。

### 3.2 向 `risk-service` 询问（必须通过）

- **时间窗**：`12:00–14:00` 禁开；
- **VIX Gate**：`VIX ≥ 20` 禁 `E1`；
- **封禁**：逐标的 `MIDFAIL_UNTIL_1400`（开盘≤15m 急跌至中轨且 10m 未回）/ `MISSED_ENTRY`（错过 E1/E2 当日禁开）；
- **事件日限制**：财报前 `3–5` 日做 T 必须“**上涨（M60 上行）或横盘（ATR%<阈值）**”；不满足则阻断；
- **IV 限制**：`IV>110%` 看涨禁止隔夜→收盘前强平；
- 风控返回 `risk_block(reason=...)` 时，执行层**直接拒单**并记录 `orders.reason_code=BLOCK:<reason>`。

> **实现**：统一方法 `precheck(signal) -> PASS / BLOCK(reason)`；通过后才进入委托构造。

## 4) 订单生成策略（简单且一致）

### 4.1 共用前置检查（全部信号）

- **流动性与 DTE/档位**：见 3.1。
- **minTick 对齐**：`limit` / `auxPrice` 四舍五入到合法价位。
- **TTL**：每单 **30s** 未成 → 撤；若信号仍有效且价差/方向未变，**仅一次**调价再挂 **30s**。

### 4.2 限价构造（Options）

> 设 `bid, ask, mid=(bid+ask)/2, sp=ask-bid, tick=minTick`。

- **市价替代（可成交限价）**：
   买入：`L_mkt = round_to_tick( min(ask, mid + 0.6*sp), tick )`；
   卖出：对称 `max(bid, mid - 0.6*sp)`。
- **被动限价（做T/等待回补）**：
   起始 `L_passive = round_to_tick( mid, tick )`；如 **15s** 无排队优势 → 改 `mid + 0.2*sp`（卖出对称）。
- **强制成交（卖点/清仓）**：
   起始 `limit=bid`（卖）或 `ask`（买回），**10s** 未成降/提 **1 跳**，最多 **3 跳**。

**选择规则**

- **E1（开盘追高）**：`可成交限价`（或 IB `Adaptive(LMT)` 可选；limit 仍取 `L_mkt`）。
- **E2/A2/A3/A4（普通进场/加仓）**：`被动限价` → 30s 无成改 `可成交限价` 再试一次。
- **S1/S2/时间清仓/IV 强平**：走 `强制成交` 路线（15s 内务必完成；未成改 `L_mkt` 一次性清完）。

------

## 5) 期权链选择与合法价格

- **selector**：`reqSecDefOptParams/reqContractDetails` → 生成 **(expiry, strike, right=Call)** 候选；
- 过滤 `DTE 2–7`、`OTM +2~+5`；按 **价差最小 → OI/Volume 最大 → 距现价最近** 排序取前 1；
- 下单前再做一次**流动性与价差兜底**；
- `reqMarketRule` 获取 **minTick** 并缓存；未命中时拒单 + 记录 `BLOCK:MIN_TICK_UNKNOWN`。

------

## 6) 订单生命周期与事件

- **状态机**：`Submitted → Partial → Filled | Cancelled | ApiCancelled | Rejected`；
- **撤补**：到 TTL 未成即撤；若仍有效且未超“仅一次”原则 → 改价再挂；
- **卖点优先**：同 symbol 遇到 `SIG_EXIT_*` 或 `SIG_TIME_CLEAR_*` → **优先取消**买单/加仓单并走清仓流程；
- **风险事件联动**：收到 `risk-service.force_close(symbol)` → 立即走 `强制成交` 路线清仓；收到 `risk_block(symbol)` → 取消未成交买单。
- **幂等**：每个信号只产生一个 `clientOrderId`；断线恢复后按 `clientOrderId` 对账补写 `fills/exec_metrics`。
